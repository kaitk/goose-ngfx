# 01: Audit ngfx against NoGraphicsAPI's intent

Status: in-progress

NoGraphicsAPI is a thin wrapper: the application owns allocation, lifetime, and
synchronization, and its utility library is optional. ngfx owns several of those
policies itself. For each policy, decide whether ngfx follows the intent, deviates for a
reason that still holds, or should change.

Rows 11 to 22 are intents the sources state that the first ten rows missed. Verdicts were
reached by reading the code at `26acba1`; nothing was built or run.

| # | ngfx choice | Tension with intent | Verdict |
|---|---|---|---|
| 1 | The module owns the descriptor heaps and gives every texture a slot | The application owns the heaps and chooses the indices | Deviates, holds |
| 2 | `update_buffer` through `UploadQueue`, and `frame_data` | Upload and frame-memory policy sit above the wrapper | Change (flush count) |
| 3 | The module places barriers for uploads, creation, read-back, the screen copy, each frame's first pass, and a pass over an earlier pass's target | Barriers are global, name producer and consumer, and aren't hidden | Deviates, holds |
| 4 | An offscreen RGBA8 screen, copied at `frame()` | One extra fullscreen pass every frame | Deviates, holds |
| 5 | Every texture is a transfer source and destination | This may cost compression | Change (depth formats) |
| 6 | All work runs on queue zero | The API has several queues and timeline points | Deviates, holds |
| 7 | Pipelines are created lazily per set of target formats | PSOs get created at points the program doesn't choose | Change |
| 8 | Slang is compiled at run time | NoGraphicsAPI precompiles shaders. Goose forces this ([findings](../../docs/goose-findings.md)) | Deviates, holds |
| 9 | No mesh or task shaders | NoGraphicsAPI supports them | Deviates, holds |
| 10 | Mips are generated by compute | The earlier work inferred this; the author never stated it | Follows |
| 11 | One root per draw or dispatch, shared by the vertex and fragment stages | All graphics stages share one root | Follows |
| 12 | Roots and per-frame data are copied into mapped frame memory | Fill roots through the CPU address of mapped storage | Follows |
| 13 | Buffers live in GPU-only memory, written through uploads | The blog's default memory is CPU-mapped | Deviates, holds |
| 14 | Viewport and scissor are commands; depth state comes from `PipelineDesc`, set at bind | Viewport, scissor, and depth/stencil are command state | Follows |
| 15 | A PSO holds the shaders, formats, blend, cull, and depth bias | PSOs keep only raster, blend, and attachment formats | Follows |
| 16 | Releases wait in a `DeleteQueue`; shutdown waits, drains, then destroys | Destruction is immediate; deferral is optional policy | Follows |
| 17 | A command pool and frame memory per frame in flight; texture initialization in its own submission | One-shot command buffers, a pool per frame in flight | Follows |
| 18 | Samples index textures and samplers with per-draw indices from the root | Standard mipmapping beats per-lane descriptors; use those only when needed | Follows |
| 19 | No indirect draws or dispatches | Indirect work takes address-based arguments | Change |
| 20 | Handles with generations, and misuse checks on every call | A thin wrapper, not a validation layer, with no shadow state | Deviates, holds |
| 21 | The window's image is acquired at `frame()` and drawn by the copy | Presentation transitions stay internal | Follows |
| 22 | No contiguous descriptor ranges | A base index can name a range of descriptors | Deviates, holds |

## Findings

Paths under `third_party/NoGraphicsAPI/` are shortened to `NGA/`. "Blog" is Sebastian
Aaltonen's [No Graphics API](https://www.sebastianaaltonen.com/blog/no-graphics-api),
cited by section.

1. **Descriptor slots. Deviates, holds.** `NGA/README.md:26-28` ("The application owns
   descriptor heaps and chooses their indices. Materials carry those indices as data");
   `NGA/include/NoGraphicsAPI/NoGraphicsAPI.hpp:748-749`. ngfx picks the slot
   (`SlotAllocator`, `native/ngfx_gpu.hpp:211-232`) and hands it out with `index(t)`, so
   indices still travel as data in roots and buffers; slot reuse waits for the GPU through
   the `DeleteQueue` (`native/ngfx_resources.cpp:127-144`), as the header requires. gfx
   programs never managed heaps, so the reason holds. Row 22 covers what is lost.

2. **Uploads and frame memory. Change.** Blog, "Modern GPU memory management" (upload is
   a CPU write to mapped memory plus a copy command); `NGA/README.md:38-40`. The policy
   holds: `update_buffer` taking effect for the whole frame spares programs every upload
   barrier, which is why the recovered sync analysis kept it. One detail breaks
   `UploadQueue`'s contract. `max_pending_batches` is `frames_in_flight`
   (`native/ngfx_device.cpp:247`), which `upload_queue.hpp:28` sizes for one flush per
   frame, but `update_texture` flushes twice per call (`native/ngfx_resources.cpp:410-412`)
   and `upload()` flushes on every overlap. A third batch in a frame makes `begin()` wait
   for the oldest on the CPU (`NGA/utility/src/upload_queue.cpp:147-151`), so two
   `update_texture` calls in one frame stall on the previous frame. Each batch is also
   bracketed by `all_commands` barriers (`upload_queue.cpp:153`, `:211`).
   Proposal: track texture destinations as buffer ranges are tracked and flush only on an
   overlap, and size `max_pending_batches` to the flushes a frame can make. No sample
   updates textures per frame, so the acceptance set doesn't see this; 02 should confirm.

3. **Module barriers. Deviates, holds.** Blog, "Barriers and fences" (producer and consumer
   stage masks only) and "Render passes" ("Render pass begin/end commands don't
   automatically emit barriers"); `NGA/docs/no-graphics-api-comparison.md:60-70`;
   `NGA/docs/vulkan-support.md:209`, `:223-224`. Every module barrier is global, names both
   scopes, and is one NoGraphicsAPI's examples or tests record (`native/ngfx_draw.cpp:155-160`,
   `:201-217`, `:361-387`; `native/ngfx_device.cpp:103-104`). The module records them only
   for work it records itself: the screen, uploads, read-back, and targets named in
   `PassDesc`. Leaving these to the program would leak the module's internals into every
   gfx-shaped program, and hidden barriers at every pass were tried first and rejected (the
   recovered `sync-analysis.md`, option (b) and table in section 1). The same-target barrier
   fires only on reuse, so passes into disjoint targets still overlap, as the blog's
   "Render passes" allows.

4. **Offscreen screen. Deviates, holds.** `NGA/docs/no-graphics-api-comparison.md:95-97`
   (presentation is outside the post); `acquire` gives only a render view
   (`NoGraphicsAPI.hpp:712-716`). The copy is what makes `screenshot`, `read_pixels`, and
   headless mode work, and gfx pays the same fullscreen blit (`docs/design.md`, "Surface"),
   so it adds no cost relative to gfx. 03 should measure it at 4K.

5. **Transfer usage on every texture. Change.** `NGA/README.md:20-22`; blog, "Modern GPU
   memory management" ("DCC and Morton swizzle are the main reasons we want to copy
   textures into a private GPU heap"), so a copy destination is the intended upload path.
   Metal has no transfer usage bit: NoGraphicsAPI maps none (`NGA/src/NoGraphicsAPIMetal.mm:126-135`),
   so the flags cost nothing there. Vulkan sets `TRANSFER_SRC`/`DST`
   (`NGA/src/NoGraphicsAPI.cpp:2588-2589`); any compression cost is driver-specific and
   unmeasured. Depth formats are the problem. Both backends reject a combined depth/stencil
   format with transfer usage (`NoGraphicsAPI.cpp:3586`, `NoGraphicsAPIMetal.mm:756-757`),
   and `create_texture` always adds it (`native/ngfx_resources.cpp:172`), so
   `DEPTH24_STENCIL8` can't be created on either. ngfx refuses to update or read back depth
   anyway (`ngfx_resources.cpp:265`, `:408`). Inferred from the code; no test creates a
   `DEPTH24_STENCIL8` texture. Proposal: add the transfer flags to color formats only; keep
   them on color for gfx parity until 03 measures a cost.

6. **Queue zero. Deviates, holds.** `NGA/docs/no-graphics-api-comparison.md:75-78` (multiple
   queues, caller-owned timeline points). No acceptance-set program needs async compute,
   M1's queue independence is unknown (`docs/design.md`, "Memory and submission"), and
   NoGraphicsAPI records device loss on an RTX 4090 with concurrent general, compute, and
   copy queues on driver 596.99 (`NGA/docs/known-driver-issues.md:15-31`). The copy-queue
   upload in `docs/design.md`'s "Open" list stays the follow-up.

7. **Lazy pipelines. Change.** Blog, "Shader pipelines" ("PSO creation is expensive, as it
   requires calling the GPU driver's low-level shader compiler"); `NGA/README.md:32-34`;
   the examples create every PSO before the loop (`NGA/examples/cube/cube.cpp:94-100`,
   `NGA/examples/deferred_renderer/deferred_renderer.cpp:173-197`). ngfx creates the PSO at
   the first draw into a new set of target formats (`native/ngfx_draw.cpp:51-76`), so the
   driver compile lands mid-frame. Laziness keeps gfx's surface and holds as the fallback.
   Proposal: let a program name the target formats ahead, either as `PipelineDesc` fields
   (color formats and depth format, defaulting to lazy) or as
   `ngfx::prepare(pipeline, PassDesc)`, and have the samples prepare their screen pipelines
   at startup.

8. **Run-time Slang. Deviates, holds.** `NGA/docs/no-graphics-api-comparison.md:49-51`
   ("There is no runtime shader compilation"); blog, "Shader pipelines" (shaders load as
   precompiled IR). NoGraphicsAPI still receives precompiled SPIR-V or metallib; the
   compile happens before it, in `ngfx::slang`, because Goose has no build hook
   (`docs/goose-findings.md`, "Shaders in an outside language compile at run time"). The
   cache in `docs/design.md`'s "Open" list is the follow-up if startup time matters.

9. **No mesh or task shaders. Deviates, holds.** `NGA/README.md:3-4` (`VK_EXT_mesh_shader`
   is required); blog, "Graphics shaders" (mesh shaders for desktop, vertex shaders still
   suited to mobile tilers). Every port is a vertex-pulling gfx program, and adding
   `create_mesh_pso`/`draw_meshlets` extends the surface without changing it. Add them when
   a program needs them.

10. **Compute mips. Follows.** The recovered `mips-research.md`: Aaltonen never wrote about
    mip generation for NoGraphicsAPI, the API has no blit, and his PETAFAB bloom is "a mip
    chain approach", where a single-pass version "would be slightly faster on PC, but not
    on mobile" (X post, pasted into that file). `generate_mips` dispatches per level
    (`ngfx.goose:765-785`), reads the level above through one sampled descriptor with an
    explicit level (`native/ngfx_mips.slang:27-32`), and writes through a per-level
    storage descriptor, which matches the plan he endorsed: "one sampled texture with
    explicit mip selection". The per-level storage slots are needed, because a storage
    write can't select its level the way a read can.

11. **Shared root. Follows.** `NGA/README.md:84` ("All graphics stages share the same
    root"); `NGA/docs/no-graphics-api-comparison.md:45-47`. `draw` passes one 16-byte-aligned
    address to both stages (`native/ngfx_draw.cpp:478-485`). The blog's "Graphics shader
    bindings" gives each stage its own pointer; ngfx follows NoGraphicsAPI's choice, and
    "one root per Slang module" is `GPU_ROOT`'s consequence.

12. **Frame memory. Follows.** `NGA/README.md:62-73`, `:85`;
    `NGA/docs/no-graphics-api-comparison.md:41-43`. 16 MB of mapped memory per frame in
    flight, bump-allocated and reset only after that slot's last submission completes
    (`native/ngfx_device.cpp:229-246`, `:327-330`), as `deferred_renderer.cpp:240-246` does.
    `root()` and `frame_data()` copy the program's bytes once more than C++ would, because
    an `extern fn` can't return a slice (Goose's `goose_spec.md` §7.10), so Goose can't
    write into mapped memory itself.

13. **GPU-only buffers. Deviates, holds.** Blog, "Modern GPU memory management" ("The
    standard memory type should be CPU mapped GPU memory"); `create_gpu_heap` defaults to
    `cpu_visible` (`NoGraphicsAPI.hpp:719`), and the examples keep vertices there
    (`cube.cpp:111-118`). ngfx buffers are `gpu_only` (`native/ngfx_resources.cpp:24-56`)
    because Goose can't write mapped memory (row 12), and writing a buffer an in-flight
    frame reads would break `update_buffer`'s whole-frame rule. GPU-only memory also avoids
    the 256 MB fixed BAR that `NGA/README.md:152-155` warns of.

14. **Dynamic state. Follows.** `NGA/README.md:32-34`; `NoGraphicsAPI.hpp:803`. `viewport`
    and `scissor` are commands (`native/ngfx_draw.cpp:443-476`), and depth test, write, and
    compare are set with `set_depth_stencil` at bind (`:92-93`), never compiled into the
    PSO. The surface ties depth state to `PipelineDesc` as gfx does, so two pipelines that
    differ only in depth state compile two PSOs; no sample has such a pair.

15. **PSO contents. Follows.** `NGA/docs/no-graphics-api-comparison.md:53-56`; blog,
    "Rasterizer state" (keep in the PSO only what changes the generated code). The PSO
    holds shaders, color and depth formats, blend, cull, and depth bias
    (`native/ngfx_draw.cpp:55-67`), with no binding or vertex layout.

16. **Deferred destruction. Follows.** `NGA/AGENTS.md:21-23`; `NoGraphicsAPI.hpp:688-690`.
    Releases join a pending list that the next submission's timeline value retires
    (`native/ngfx_device.cpp:23-33`, `:159-171`), and `ngfx_gpu_close` waits idle, drains
    the `DeleteQueue`, then destroys (`:267-308`), in `AGENTS.md:23`'s order.

17. **Command buffers. Follows.** Blog, "Command buffers" ("one shot command buffers (a
    resettable command pool per frame in flight)"); `NoGraphicsAPI.hpp:767-769`. Two pools,
    reset after a timeline wait (`native/ngfx_device.cpp:325-333`), with the heaps set on
    every buffer because bindings aren't inherited (`:37-41`). Texture initialization is
    submitted on its own before any upload (`native/ngfx_resources.cpp:189-193`), as
    `upload_queue.hpp:20` requires and `cube.cpp:145-148` does; that is one submission per
    texture created, which only matters to a program creating textures every frame.

18. **Descriptor use in shaders. Follows.** Aaltonen's X post, pasted into the recovered
    `mips-research.md`: "Standard mipmapping is faster than indexing descriptors. Same for
    Texture2dArray. Only use per-lane descriptors when needed." Every sample and the ui
    renderer read a texture and sampler index from the root, uniform across the draw
    (`samples/mini_doom.goose:1345-1347`, `samples/mini_minecraft.goose:933-934`,
    `ngfx_ui.goose:69-70`), and pack artwork into one atlas, so none needs
    `gpu_nonuniform_index`. Separate sampler indices follow
    `NGA/docs/no-graphics-api-comparison.md:35-37` rather than the blog's embedded samplers.

19. **No indirect work. Change.** `NGA/docs/no-graphics-api-comparison.md:80-83`; blog,
    "Indirect drawing" ("a single GPU pointer instead of the usual buffer object + offset
    pair"). GPU-written roots already work, since `draw` takes any address, but
    `draw_indirect`, `draw_indexed_indirect`, and `dispatch_indirect`
    (`NoGraphicsAPI.hpp:817-821`) have no ngfx counterpart, so GPU-driven culling can't be
    written. Proposal: add the three, taking a buffer and offset for the arguments; the
    existing `STAGE_INDIRECT` and `ACCESS_INDIRECT_READ` points order them.

20. **Validation. Deviates, holds.** `NGA/AGENTS.md:17-19`, `:28`. ngfx keeps handle tables
    with generations (`native/ngfx_gpu.hpp:41-126`) and checks every call, because a Goose
    program gets gfx's contract: misuse is reported and aborts at `frame()`, never a crash.
    The cost is a table lookup per call; 02 should check it stays off the per-draw path.

21. **Presentation. Follows.** `NGA/docs/no-graphics-api-comparison.md:95-97`. The window's
    image is acquired last, drawn once by the copy, and presented by the submission that
    acquired it (`native/ngfx_device.cpp:310-324`), holding it for the shortest time.

22. **Descriptor ranges. Deviates, holds.** Blog, "Texture bindings" ("A single index can
    also represent the starting offset of a range of descriptors");
    `deferred_renderer.cpp:87-90`, `:361` uses a base index. ngfx's slots come off a free
    list (`native/ngfx_gpu.hpp:217-226`), so consecutive textures aren't contiguous and a
    shader can't compute `base + i`. Programs can still store each index in a material
    buffer, which no sample needs beyond. Add ranges only when a program wants GPU-computed
    indices.

## Proposed follow-ups

- [x] Upload batching (row 2): flush `update_texture` only on overlap, and size
  `max_pending_batches` to a frame's flushes. Done in `7c04663`.
- [x] Transfer usage (row 5): drop the transfer flags from depth formats, which also makes
  `DEPTH24_STENCIL8` creatable on Vulkan; add a test that creates one. Done in `70969e1`.
  Metal has no 24-bit depth, so there `DEPTH24_STENCIL8` falls back to 32-bit float depth
  with stencil.
- Eager pipelines (row 7), task 005: a way to name a pipeline's target formats at creation, used by
  the samples.
- Indirect commands (row 19), task 006: `draw_indirect`, `draw_indexed_indirect`, and
  `dispatch_indirect`.
- For 03: measure the screen copy (row 4), transfer usage on color targets (row 5), and the
  per-call handle checks (row 20).
