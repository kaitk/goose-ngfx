# 01: Audit ngfx against NoGraphicsAPI's intent

Status: todo

NoGraphicsAPI is a thin wrapper: the application owns allocation, lifetime, and
synchronization, and its utility library is optional. ngfx owns several of those
policies itself. For each policy, decide whether ngfx follows the intent, deviates for a
reason that still holds, or should change.

| ngfx choice | Tension with intent |
|---|---|
| The module owns the descriptor heaps and gives every texture a slot | The application owns the heaps and chooses the indices |
| `update_buffer` through `UploadQueue`, and `frame_data` | Upload and frame-memory policy sit above the wrapper |
| The module places barriers for uploads, creation, read-back, the screen copy, each frame's first pass, and a pass over an earlier pass's target | Barriers are global, name producer and consumer, and aren't hidden |
| An offscreen RGBA8 screen, copied at `frame()` | One extra fullscreen pass every frame |
| Every texture is a transfer source and destination | This may cost compression |
| All work runs on queue zero | The API has several queues and timeline points |
| Pipelines are created lazily per set of target formats | PSOs get created at points the program doesn't choose |
| Slang is compiled at run time | NoGraphicsAPI precompiles shaders. Goose forces this ([findings](../../docs/goose-findings.md)) |
| No mesh or task shaders | NoGraphicsAPI supports them |
| Mips are generated by compute | The earlier work inferred this; the author never stated it |

## Acceptance criteria

- [ ] Each row has a verdict (follows, deviates with a reason that holds, or change), and
      each verdict cites a line of NoGraphicsAPI's docs or a section of the blog post
- [ ] Any intent the sources state that the table misses is added as a row
- [ ] Each "change" verdict either has a task of its own or updates `docs/design.md`
